- **Two-page layout (2026-08-24 re-layout).** The old single-column stack composed to 767 × 2393 pt (aspect 3.12), which fit-scales to ~41% of a letter page — the worst width utilization in the figure set. Now two pages with letters A–Q running continuously (same pattern as figS04 / figS07, so no citation or legend re-lettering): **page 1** = `panel_libqc` (A–E) / `panel_genotype_qc` (F–H) / `panel_clustering` (I–K), single column, every tile ~full page width (639 × 994 pt, 83% letter-width utilization, ~97% row fill); **page 2** = `panel_demux_validation` (L–N) + `panel_I_cell_counts_staging` (O) on row 1, `panel_pipeline.svg` (P) + `panel_Q_g2_breed` (Q) on row 2 (1062 × 1116 pt, 100% letter-width utilization; row 2 is a horizontally centered pair filling 70% of the page width). The pairings are semantic: L–N and O share the stage-ordered genotype axis; Q motivates the GEX03-specific variant discovery drawn in P. A brute-force search over every order-preserving row partition and page split confirmed this is the maximum achievable panel scale (0.576 vs 0.464 for the next-best candidate that keeps ≥70% width utilization on both pages).
- **Panels A/C axis text:** resolved 2026-08-21 — panels rebuilt with the "nucleus"/"nuclei" labels.
- **Panel E (2026-10-12 rebuild, all 12 libraries):** both rates now come from one table, `figures/data/step02e_doublet_comparison.tsv`, written by the production QC step `pipeline/c1_qc_filter.py` (QC-passing nuclei x scDblFinder class x consolidated vireo genotype status). The two rates use **different denominators**: scDblFinder rate = scDblFinder doublets / all QC-passing nuclei; vireo rate = vireo doublets / scDblFinder singlets retained in the consolidated genotype map `cb_genotype_map_v2.tsv.gz` (`genotype_status` singlet, doublet or unassigned), homotypic-corrected by 1/(1-1/N) (N = genotypes vireo can resolve per lane; see the homotypic-N note below). This is not the same as "every nucleus with a vireo call": the map builder `FC_08656/20260326_35_produce_cb_genotype_map_v2.py` skips every G3 vireo row whose `donor_id` is in `G3_EXCLUDE = {'donor6'}` (the chick contaminant; a singlet call by construction) before writing the map, so those nuclei join as `no_genotype` in `c1_qc_filter.py` and are excluded here. (The same builder also keeps only `donor29` GEX05 rows from the G6 dp500 run and recodes G2 `unmapped*` donors to `unassigned`; neither reduces coverage here, since GEX05 is 100% genotyped through G6 libpair and `unassigned` stays in the denominator.) The vireo rate is therefore conditional on passing scDblFinder (e.g. GEX08: 8.19% among 20,713 genotyped scDblFinder singlets vs 33.33% over all 29,991 QC-passing nuclei, both homotypic-corrected, because 7,543 vireo doublets are also scDblFinder doublets). Nuclei with `genotype_status == no_genotype` are absent from the consolidated map (no vireo call in any run the map uses, or a call the map builder drops as above) and are excluded from the vireo denominator (2026-10-13; the first rebuild had counted them as non-doublets). `generate_libqc.py` raises if a library has no genotyped scDblFinder singlets or if its genotyped fraction falls below `VIREO_COVERAGE_FLOOR` = 0.50. The previous panel took vireo rates from the older `step02_doublet_comparison.tsv` (2026-03 step02d vintage), which never contained GEX04/GEX0S-duck, so their squares were blank (the submitted legend disclosed this as "10 of 12"). Splicing the two G3 rows from a different vintage was rejected; rebuilding the whole panel on the production table removes the gap. Values shift by up to ~3.8 points for the vireo rates (GEX05, 15.61% -> 11.80%) and ~2.0 points for scDblFinder (GEX03-2, 27.68% -> 29.63%) relative to the submitted panel; no number from this panel is quoted in the text. Cross-check: the original per-cell G3 inputs were recovered from standby (`duck_backups/scratch_20260422/universal_genotyping/group3/vireo_N11_denovo_best/donor_ids.tsv`, md5 c24cafe1...; `phase2_scdbl_rerun_20260821/step02b_scdblfinder_g3.tsv`, md5 ca03d307..., byte-identical to the 2026-05-12 backup copy).

- **Panels B/C, all 12 libraries (2026-10-13).** `step01_cellranger_metrics.tsv` previously lacked GEX04 and GEX0S-duck (the d2c producer `pipeline/d2c_parse_cellranger_metrics.py` skips a library whose `metrics_summary.csv` is absent on scratch), and `_load_cellranger_metrics()` silently filtered to the libraries present, so B/C showed 10 of 12. The two rows were transcribed by hand from the standby cellranger outputs (`STANDBY_FC/GEX04_GEX/outs/metrics_summary.csv`, `STANDBY_FC/GEX0S-duck_GEX/outs/metrics_summary.csv`) and inserted in the producer's `LIB_DIRS` order; GEX05's standby file matched its committed row exactly, confirming the same cellranger run. New values: GEX04 saturation 75.2%, mean reads/nucleus 27,971; GEX0S-duck saturation 90.2%, mean reads/nucleus 92,809. GEX0S-duck is a mixed duck/chick lane, so its cellranger metrics (4,261 estimated cells, high reads per cell) include chick nuclei. `reads_mapped_transcriptome` is blank for every row, including the two new ones: the producer's `TARGET_METRICS` name does not match the cellranger column (not fixed here; the column is unused by any figure). `_load_cellranger_metrics()` now raises if any `LIB_ORDER` library is missing, duplicated, or lacks saturation / mean reads. (Panels A and D read other tables; they were brought to 12 libraries separately, see the panels A/D note below.)
- **Panel E shown as a progression (2026-10-13).** The vireo rate stays conditional on scDblFinder singlets (homotypic-corrected), and the connector is an arrow scDblFinder -> vireo, so the panel reads as "transcriptome call on all nuclei, then the additional cross-genotype doublets vireo finds among the remainder". This is how the submitted panel was computed too: its source table (`step02_doublet_comparison.tsv`, 2026-04) holds scDblFinder singlets only (e.g. submitted GEX05 15.6% = 2,734 / 19,465 / 0.9). An all-nuclei vireo rate was tried and rejected: in the GEX03/GEX04 pools ~94% of scDblFinder doublets carry no vireo call (vs ~3% of singlets), so an all-nuclei vireo rate there is not comparable. Why those nuclei lack a G2/G3 vireo call is not established (the G2/G3 cellSNP barcode lists are undocumented); the conditional rate is unaffected by it. The chick library-QC panel (`figS04_supp` A) plots a raw, all-cells vireo rate and is not meant to match this panel.

- **Panel E homotypic N and the GEX0S-duck exclusion (2026-10-13).** N in 1/(1-1/N) is the number of duck genotypes vireo can resolve per lane (library), not the number designed into the pool. GEX04 N = 9: 10 embryos were designed, but one is undetectable by both the 2024 ARC and the 2026 GEX pipelines, and vireo resolves 9 duck genotypes (genotype consolidation record, not distributed). GEX04 vireo rate 6.97% -> 7.06%. All other N unchanged. The GEX0S-duck vireo square (previously 3.62%) is omitted via the declared constant `VIREO_NOT_COMPARABLE` in `generate_libqc.py`: it is a mixed-species lane (4 duck + 4 chick embryos); on the duck alignment the 4 chick embryos collapse into one vireo genotype and chick singlets are excluded from the duck genotype map, so the homotypic-corrected vireo rate is not comparable. Its scDblFinder circle (6.71%) stays. Any other library with missing or low (< `VIREO_COVERAGE_FLOOR`) genotype coverage still raises.

## Proposed manuscript S8 B/C/E legend text

"(B) Per-library sequencing saturation and (C) mean reads per nucleus for all 12 libraries; GEX0S-duck is a mixed duck/chick lane, so its metrics include chick nuclei. (E) Per-library doublet rates as a two-step progression: scDblFinder ( transcriptome-based, filled circles) as a fraction of all QC-passing nuclei, then vireo ( genotype-based, open squares) as the fraction of the remaining scDblFinder singlets that vireo additionally calls doublets (arrows), corrected for homotypic doublets using the number of duck genotypes vireo resolves per library. Doublet removal uses vireo calls only (scDblFinder retained as QC metadata). No vireo rate is shown for GEX0S-duck, a mixed duck–chick lane in which the chick embryos form a single genotype."
